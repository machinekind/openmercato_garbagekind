## 3. Protocol / API details

**CAN**
- Feedback frame id `0x052`, 48 bytes, 200 Hz.
- Bring-up: `ip link set can0 type can bitrate 1000000 dbitrate 5000000 fd on sample-point 0.875 dsample-point 0.875`, plus `ip link set can0 txqueuelen 65...` (t=09:53).
- Enable/engage sequence referenced repeatedly as **"FF 1→5→6"** handshake — required before an inference process can drive the arm.
- Group-7 (gripper) `p_des` scalar: linear at **57.1 deg per unit of p_des**, range `-2.0` (open) … `0.6` (closed); force-freeze if `|effort| > 1.2` while closing.

**LeRobot v3 dataset schema** (from `record_a1x.py` and the real dry-run episode):
- `action`: float32(7) = 6 joint targets (rad) + gripper `p_des`.
- `observation.state`: float32(7) = measured joints (`arm.q[:6]`) + group-7 raw position (gripper proxy — **not verified gripper position**, per `docs/PROTOCOL.md`).
- `observation.images.side`, `observation.images.robot`: 640×480 video, 30 fps target.
- Per-frame `task` string used as language conditioning, e.g. `"put the cola can in the left bin"`.
- Real sample episode: 292 frames / 10 s = 29.2 fps effective.

**Webpanel HTTP/WS (as built this session)**
- `GET /health` — camera frame counts + `last_error`, arm state (`q`, engaged), used everywhere for polling.
- `GET /stream/robot`, `GET /stream/pc` — MJPG camera streams.
- `POST /api/event` — chat message injection, `{"from":"operator"|..., "kind":"chat", "text": "..."}"`; after security fix, `from:"operator"` **cannot be forged over unauthenticated REST** — reserved for the operator WS path.
- `POST /api/command` — raw motion dispatch (`goal`, `jog`, `grip`, `engage`, `enable`); after CRITICAL fix, **allowlisted by transport**: `via="api"` (i.e. the DGX agent) may only send `{engage, disengage, preset, pantilt, chat}` — `goal`/`jog`/`grip`/`enable` restricted to the operator WS.
- `GET /api/events?since=0` — event/status log (ring buffer, `deque(maxlen=200)`).
- `GET /shadow/pred` — shadow GR00T prediction JSON: `{"ok":true,"n":<counter>,"latency_ms":...,"task":"...","frame_ages":...}` (v1, pull-based, replaced).
- Shadow **push** endpoint (v2): DGX POSTs predictions to the panel over the cable (`10.42.0.1:8080`) because DGX cannot be reached inbound.
- Radar/map endpoints: agent pushes world-map JSON (`{sector° → objects, timestamp}`) to panel; panel serves it and renders a 30°-sector semicircle with a live needle.
- WS message dispatch in frontend keyed on `m.type === "event"`.

**Env vars**
- `HF_HOME=$HOME/groot/hf_cache` (DGX) — required because `~/.cache/huggingface` is root-owned, no sudo to fix.
- `OLLAMA_CONTEXT_LENGTH=32768` — ollama's default context silently truncates otherwise.
- `SORT_HOME="j1,j2,j3,j4,j5,j6"` (degrees) — chosen episode start pose for the (later-deleted) sorting recorder.

## 4. Grasping / "pick up the can" pipeline

This is the "Track B" garbage-sorting plan (t=10:45 plan, t=10:47 "Go with Track B"). **It was built partway, never completed a real recording, and was fully deleted** at t=12:14 when the user pivoted to the monitoring-system project.

**Model chosen:** GR00T N1.7-3B (NVIDIA, LeRobot `groot` policy), `embodiment_tag=new_embodiment`, relative actions with gripper excluded from the relative transform.

**Why GR00T over SmolVLA/pi0.5 first:** "smoothest Spark citizen — first-party GB10/CUDA 13 support + official DGX Spark fine-tune playbook" (t=18:55). Ladder considered: ACT (sanity check) → SmolVLA-450M (first real VLA, SO-101-pretrained) → pi0.5/GR00T (big guns, DGX-sized).

**Zero-shot GR00T results (offline smoke test, t=09:43-09:53):**
- Model load: 4.2 s from cache, 3.14B params.
- VRAM: 12.6 GB at load, 13.3 GB peak (of 128 GB unified — "GB10's 128 GB laughs at it").
- Steady-state chunk inference: **242 ms per 40-step action chunk**; within-chunk steps 12-16 ms; first-call warmup ~3-10 s (not representative).
- Action outputs: normalized garbage/noise (0..1 range) — expected, because `new_embodiment` head is randomly initialized and there are no dataset normalization stats.
- Blocker hit: preprocessor pulls tokenizer from **`nvidia/Cosmos-Reason2-2B`** (N1.7's backbone), which is **gated on HuggingFace** — 401 until the user accepted the license and logged in (`hf auth login`).

**Why zero-shot is garbage — explained to user (t=10:38):** GR00T = (1) pretrained vision-language backbone (3B, genuinely understands images+text) + (2) an action head that is only pretrained for embodiments NVIDIA shipped (GR1, DROID Franka, SO-101...). A1X gets `new_embodiment` = freshly initialized random weights, plus no normalization stats exist without a dataset. Fine-tuning on ~30-50 demos is what "wires" the backbone's understanding to A1X's joint space; a borrowed head (e.g. DROID's) would output wrong-robot commands.

**Shadow mode (built, worked):** DGX pulls both camera streams + arm state, runs GR00T ~1-2 Hz, pushes predicted 40-step chunk to panel; panel overlays predicted (blue) vs actual (dashed) per-joint curves. Verified end-to-end: prediction counter climbing, latency 249-273 ms, camera frame ages ~0.03 s, arm state age ~0.11 s (t=10:23, t=10:29). Confirms plumbing only — "don't expect sense in the curves... Action head for your arm is randomly initialized."

**Bounded live execution (built, worked):** "Execute on arm" toggle in panel. Cage: each policy step clamped to **±10° of current pose**, gripper **never touched**, 30°/s slew cap + URDF limits still apply underneath, execution only while Engaged, STOP/disengage/stale-feedback kills it instantly. Verified: "EXEC ON — N steps", arm did a slow pseudo-random wander (as predicted for an untrained head) — "full closed-loop stack proven live (2 cams → cable → GB10 inference → push → CAN @ 200 Hz)."

**Camera config decided for training:** two views — `robot` (DGX arm-mounted cam) + `side`/`pc` (fixed third-person). Rule stated: **camera set at fine-tune time = camera set at inference time forever**; wrist/robot cam "measurably helps grasp precision" per NVIDIA guidance.

## 6. Gotchas and failure modes discovered

- **`KeyError: 'input_ids'`** — calling `GrootPolicy.select_action` with raw inputs instead of routing through the proper pre/post-processor pipeline (t=09:43). Fixed by rewriting the test script to use the processors.
- **HF cache root-owned** — `~/.cache/huggingface/hub` on DGX was root-owned with no sudo to fix; workaround is `HF_HOME=~/groot/hf_cache` (t=09:35).
- **Gated tokenizer dependency** — GR00T N1.7's preprocessor silently depends on `nvidia/Cosmos-Reason2-2B`'s tokenizer, which is **gated** on HF and returns 401 without login/license acceptance (t=09:43-09:47). Non-obvious dependency for a model that "isn't gated" itself.
- **`pkill` self-kill trap** — launching a new background process and `pkill`-ing the old one **in the same ssh command line** repeatedly caused the pattern match to also kill the new launch (the command-line text itself matched the pkill regex). Recurred at least 4 times across the session (t=09:59, t=10:18, t=10:23, t=13:19). Fixes used: split kill and launch into two separate `ssh` calls; use bracket-escaped exact patterns like `pkill -f "shadow_groot[.]py"` or `pkill -f "a1x[.]main"`.
- **`--allow-missing` flag not threaded through** — belonged to `so101_bridge`'s CLI but `record_a1x.py` didn't pass it to `SO101(...)`; required a source patch (t=11:04).
- **Calibration id mismatch** — calibration file named `my_leader_arm.json` but the SO101 default cal-id constant was `my_leader` (t=11:04).
- **`record_sorting.sh` used `exec`** — replaced the shell process so its `trap ... EXIT` cleanup never fired, leaving orphaned `ffmpeg` holding the v4l2loopback device across restarts (t=11:04).
- **v4l2loopback flaky** — `video_nr=10` parameter was ignored on first load (landed on `/dev/video2`); needed `modprobe -r` + reload with `exclusive_caps=0 max_buffers=4`; also something (pipewire/wireplumber or a stray process, pid 78332) held the device and had to be `fuser -k`'d (t=11:04).
- **Orphan camera processes after every panel restart** — old `ffmpeg` (laptop) and `gst-launch` (DGX) instances kept holding ports 8097/8080 and camera devices after `kill`, showing "0 frames" until manually hunted down and killed; happened repeatedly across the session (t=10:10, t=10:13, t=10:18, t=10:29, t=10:38, t=11:04).
- **Old panel ignored SIGTERM** — open aiohttp stream connections hung graceful shutdown; required `kill -9` (t=10:18).
- **DGX inbound firewall blocks everything** — discovered mid-build that the panel could never reach `DGX:8098`; the whole shadow architecture had to be flipped from pull (panel→DGX) to **push** (DGX→panel) (t=10:18).
- **SSH launch/kill race** — `setsid nohup ... &` sometimes didn't "stick" because the ssh session tore down before the fork completed; recurring failed background tasks (exit 255/1) at t=13:17, t=13:19, t=13:25 required careful re-verification with `pgrep` and sometimes multiple relaunch attempts.
