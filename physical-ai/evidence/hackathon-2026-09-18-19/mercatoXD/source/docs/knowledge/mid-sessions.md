## 3. Protocol/API details

- CAN frame IDs: `052` = feedback (48-byte CAN FD payload, e.g. payload head `FA AB FF FD FF 37…` on can0 arm, `00 93 FF FD FF AA…` on can1 arm — different joint values confirm two distinct physical arms); `054` = low-rate aux/gripper frame (can0 only, 2 frames/2s); `055` = identity/info frame (64-byte, ASCII serial payload, e.g. `36 31 31 37` = "6117").
  (d6b203b1, t=18:46)
- MIT-mode joint command frame id: `0x050`, sent @ 200 Hz, params `KP=20`, `KD=1`. (0eea018c, t=17:22)
- `dgx-agent/g05_client.py` obs schema: `embodiment_type: "galaxea_r1lite"` (line 111); `left_arm`/`left_gripper` populated from CAN (lines 106-109); `right_arm`/`right_gripper` currently zero-filled, `right_wrist_rgb` a black image placeholder. (d6b203b1, t=18:44)
- G0.5 (Galaxea) unified action space: 27-dim = `left_control(9) | left_gripper(1) | right_control(9) | right_gripper(1) | lower_body(7)`; fixed slot layout, zero-pad unused parts; model supports `dropout_noop_parts` / `absent_key_fill_value=-100` for genuinely-absent parts (recommended over sending fake zeros for the torso). (d6b203b1, t=18:44)
- `so101_web.py` HTTP API: `GET /` (page), `GET /state` (JSON snapshot), `GET /events` (SSE stream of joint state). Joint bars: arm joints shown −100..100 center-zero, gripper 0..100 left-fill. (90770e1c, t=21:55)
- RECAP (exla-ai/fla, OpenPIE) training signal — no hand labels needed: reward = time-to-completion; `advantage = V(o_t) − (episode_len − t)`; indicator `I_t = 1 if advantage > 0`; train policy `π(a | o, I)`; at inference always feed `I=1`. Every LeRobot episode's boundary already supplies this — existing recordings work as-is, including failed episodes (should be kept, not deleted, since RECAP needs mixed success/failure data). (3f89b752, t=14:37)
- OpenPIE-0.6 architecture: Policy 5.91B params (SigLIP 384 → PaliGemma/Gemma-2B VLM → Gemma-2B action expert w/ cross-attn); separate value function 1.31B (distributional, 1024 bins); action space 14D continuous, horizon 50, 22 act/s; pure PyTorch (no JAX), Apache 2.0. Checkpoint trained ONLY on `lerobot/aloha_sim_transfer_cube_human` (toy sim task) — benchmarks (action MSE 0.010, value corr 0.986) are regression fit, not real task success; weights are near-worthless as a foundation policy for A1X, but the RECAP training code is valuable. Code: `github.com/exla-ai/pi-openpi` (redirects to `exla-ai/fla`). (3f89b752, t=14:35 & t=14:37)
- A1X action dim = 7D (6 joints + 1 gripper) per `record_a1x.py:154`; OpenPIE checkpoint is 14D bimanual ALOHA — head-dim mismatch means `pi05_base` (LeRobot port of π0.5, real-robot pretrained) is the better init than the OpenPIE checkpoint itself. (3f89b752, t=14:37)
- FLA finetune CLI (for A1X on `pi05_base`):
  ```
  python scripts/create_finetune_config.py --name pi06_a1x --datasets "<you>/a1x_task" --prompts "pick up the candy" --action_dim 7
  python scripts/compute_norm_stats.py pi06_a1x
  python scripts/finetune.py --recipe pi0_frozen_backbone --repo-ids <you>/a1x_task --repo-id-to-prompt "<you>/a1x_task:pick up the candy" --action-dim 7 --exp-name a1x_v1
  python scripts/train_recap_pytorch.py --config recap_a1x --exp_name a1x_recap_v1
  uv run scripts/serve_policy.py policy:checkpoint --policy.config=pi06_a1x --policy.dir=checkpoints/.../30000
  ```
  Use the PyTorch scripts, not JAX (GB10/DGX Spark is aarch64/sm_121/CUDA13 — JAX wheels are a fight). Note: `train_recap_pytorch.py` targets Gemma-3-4B + `gemma_860m` expert, not the 2B claimed on the HF card. (3f89b752, t=14:37)
- FLA multi-dataset co-training does automatic zero-padding across datasets of different action_dim, e.g. `repo_ids=("OpenGalaxea/...R1Lite_slice", "<you>/a1x_task")` with `action_dim=14` and the 7D A1X data zero-padded. (3f89b752, t=14:45)

**VLA generalization axes** (from Q&A, no source paper fetched beyond stated knowledge):
1. Language/semantic — strongest, near-free due to web-scale VLM backbone pretraining (novel nouns, synonyms, rephrasing).
2. Visual/scene — moderate; new backgrounds/lighting/distractors OK-ish, big shifts (table height, clutter density) degrade; fix = data diversity, domain randomization.
3. Motor/physical action — weakest; interpolates seen trajectories, barely extrapolates; new embodiment needs finetune; novel dynamics (heavier/slippery objects) fail.
Composition (chaining seen skills) = middle ground, brittle for long horizons.
Key limiter: generalization ceiling is set by **action-data breadth, not language breadth** — language is cheap (web-scale), action is expensive (teleop). Diversity of poses/scenes per skill beats more shallow skills. Cited scaling-law claim (π0.5 paper, unfetched in this session): generalization to new homes/scenes improves log-linear with number of distinct environments in data, not raw episode count.
